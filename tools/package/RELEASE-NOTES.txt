CTR Reload @VERSION@ (@BUILD@) - Release notes
==============================================

This version is for track authors who test their own tracks with
Reload Studio.


DECISIONS
---------
- Windows only. There is no Linux version, and none is planned. Linux build
  files in the source code are not maintained.
- Bug reports go to GitHub issues with the "Bug report" form, see section 8
  of README.txt:
  https://github.com/LinksTech/CTR-Reload-Edition/issues/new/choose
- The package ships the game and Reload Studio. The track packer rldpack is
  built into Reload Studio and is not a separate program in the package.


NEW IN 0.7.5 BETA
-----------------
- Version numbers: 0.7.5 follows 0.0.5. From now on versions count 0.x.y
  in steps of 0.0.5 (0.7.5, 0.8.0, 0.8.5 ...).
- Shadow and exhaust per character: a .rldchar can say how its ground
  shadow and its exhaust look - the original ones, a shadow fitted to the
  model's footprint, no shadow, the exhaust at one or two points of the
  model, or none. The exhaust smoke and the turbo flames follow these
  points; with no exhaust both are hidden. A file without these values -
  every file built before - is drawn as before, and a value the game
  cannot use only brings back the original look. Only the drawing
  changes: a race runs the same with and without them.
- For scripts: rldpack make-char --shadow retail|auto|off and
  --exhaust retail|off|x,y,z[;x,y,z] (points in game units of the
  finished model). rldpack info names the look.
- Models in glTF 2.0: make-char --model and char-wheel read a .glb
  (recommended) or a .gltf (with its .bin and textures next to it, or
  embedded). All meshes of the scene become one driver, as with an OBJ.
  Base colour, base colour texture, emission, vertex colours (COLOR_0)
  and the alpha mode are read like the materials of an OBJ, and the same
  rules, budgets and messages apply. A Blender export with the default
  settings (nose toward -Y, +Z up) stands right with the default axes.
  Textures embedded in a .glb are copied to the TEMP folder for the run
  (rldpack-gltf-<hash>-<n>.png or .jpg) and removed when it ends; no
  folder to write to is the error model-gltf-temp. A broken file
  (model-gltf-broken), a file without a mesh (model-gltf-empty) and
  lines or points instead of triangles (model-gltf-mode) are refused.
  OBJ and PLY stay as they are.
- Reload Studio: the file dialogs for the model and the wheels list
  "glTF binary (*.glb) - recommended" first, then OBJ and PLY. A .glb or
  .gltf dropped onto the page is the model (on the card Wheels: the
  wheel model). The field is now called "Model file". A glTF counts as
  an OBJ for the page: Textures folder, Vertex colors, Native model and
  wheels.
- Reload Studio: the Character page switches to a compact layout when
  the window is small and fits 1366 x 768 at 150 % without scrolling.
- Reload Studio: a new 3D preview on the Character page. Drag to turn
  the model and to look from higher or lower, drag with the right or
  middle mouse button to move it, turn the mouse wheel to zoom to the
  point under the pointer (50 to 800 %), double-click for the start
  view. A bar in the preview and its View menu (also on a right click)
  hold the fixed views Front, Side, Back, Top, 3/4 and Race (the chase
  camera of the race), Reset view, a dark or light background, the Crash
  size reference, Shadow and Exhaust. These switches only change what
  you see; what is built is still chosen on the tab In-game look. None
  of them is remembered; every start begins with the 3/4 view.
- Reload Studio: a file named portable.ini next to ReloadStudio.exe (it
  may be empty) keeps its settings, logs and temporary files in that
  folder, as --settings <file.ini> does; a --settings switch still wins.
  With either, rldpack, which Reload Studio runs, keeps its temporary
  files there as well (it used to write them to %TEMP%).
- Fix: in an arcade cup the custom driver is kept at the podium instead
  of being dropped with a warning. After the cup the game returns to the
  title, and the driver select starts on the template's tile, as after
  any race.
- Fix: an OBJ material with map_Kd and an emission colour (Ke) but no
  Kd of its own keeps its texture colours (Ke used to darken it). This
  also changes the file of such a model built without preview features:
  build it again to get the right colours.
- For scripts: a switch value longer than its buffer is refused instead
  of cut, before the first window, with exit code 64. --shot takes up to
  128 entries of any length (a list used to be cut after 511 characters),
  --shot-name and --dump-prefix up to 1023 characters (was 255). A --log
  path over 511 characters now ends the start instead of falling back to
  the standard log. A shot or dump file that cannot be written says so in
  the log.

ANIMATIONS FROM SHAPE KEYS
- A glTF can bring the driver's animations as shape keys (morph targets)
  of the driver mesh: steer_left, steer_right, reverse, crash, jump, win
  and lose, each optional, upper or lower case alike (docs/ANIMATIONS.md
  in the source code). The base mesh is the neutral pose; each key is
  the full pose.
- steer_left and steer_right: the lean at full lock (frame 0 full left,
  frame 10 neutral, frame 20 full right), weighted along the steering
  curve of the original drivers. reverse: 7 frames, from 0 to full.
  crash: 15 frames along the pitch curve of the original bump, full at
  the strongest point. jump: 4 frames, from 0 to full. These go into the
  47 frames of the classic model (CMDL) and of the high-detail model
  (POSN): the game is unchanged for them, and every version shows them.
- Mirror rule: with only one steering key the other side is its mirror
  image (x -> -x) when at least 98 % of the points find a partner within
  0.5 % of the model's width (info pose-mirrored). Otherwise both sides
  keep the automatic lean, with the warning pose-not-symmetric "model not
  symmetric, using automatic lean".
- A missing key keeps the automatic pose (win and lose: neutral); a key
  that is exported but empty keeps that pose still. Unknown names are
  ignored (warning pose-unknown-key). The kart stays still: where a key
  moves the kart it is set to 0 (warning pose-kart-moved). A key that
  makes the model too big is the error model-scale. With --poses still,
  with --remesh on or without a driver part the keys are not used.
- win and lose: a new optional section MRPH in the CNET chunk holds them
  for the high-detail model, so only with --native-model on (960016
  bytes at 20000 vertices with both targets). After the finish line of
  a race with a real placing (not in a time trial) the game blends the
  native driver from the neutral pose to win (places 1-3) or lose
  (places 4-8) in 8 steps over about half a second. The steps are
  computed while loading (7.3 MiB at 20000 vertices for both); only the
  drawing changes, the race runs the same. The classic model stays
  neutral.
- A glTF with a rig (skin) is refused: model-rig "Rigs are not supported
  yet, please use shape keys".
- For scripts: make-char prints a line @pose <name> <state> <reason> for
  each of the seven (state from-file, automatic, mirrored, neutral or
  error). rldpack char-poses --model <x.glb> prints the same lines
  without writing a file; its PLY folder form stays.
- Without shape keys, and for every OBJ or PLY, the file is byte for
  byte the one built before.
- Reload Studio, card Animations (tab Extras): open without a start
  switch, no longer "Coming soon". It lists the seven poses with where
  each comes from (from the file, mirrored, automatic, neutral, or an
  error with its reason) and names ignored shape keys and a refused rig.
  Its preview: a slider Steering from left to right, Jump, Crash,
  Reverse, Win and Lose (one at a time) and Play (loop); a click on a
  pose in the list shows it. Nothing of it is built or remembered.
- Reload Studio preview: all 47 frames of both models, and win and lose
  blended on the Native look; the Classic look stays neutral after the
  finish line, as in the game.
- Reload Studio, card Animations: without "Native model" win and lose
  are not built; the list says "used only with the native model" and
  Win and Lose are greyed out.
- A driver template for Blender (CC0 1.0, free for any use): a simple
  placeholder driver with kart at the right size (1 Blender unit = 1 m
  = 64 game units) and orientation, with the seven shape keys (jump,
  crash and reverse empty and muted, so the game moves those itself)
  and the glTF export settings stored in the file (collection Driver >
  Exporters). It is a download of its own on the release page:
  driver-template.blend (made with Blender 5.2; older versions may not
  open it), with LICENSE-template.txt, the guide as ANIMATIONS.txt and
  SHA256SUMS.txt. The .blend is not in the source code or the package;
  they carry the script that makes it (folder templates:
  make_driver_template.py, LICENSE, README.md), and the same Blender
  version makes the same bytes from it:
  blender --background --factory-startup --python
  templates/make_driver_template.py
  docs/ANIMATIONS.md, the guide, is in the package as well.

PREVIEW: HIGH-DETAIL CUSTOM CHARACTERS (off by default)
- A new native render path draws a custom character from a second,
  high-detail model in the .rldchar (chunks CNET and CTXT, see
  docs/CONTAINER_FORMAT.md in the source code): up to 20000 vertices,
  30000 triangles, 64 materials and 16 textures (PNG, 16 to 2048), in
  all 47 animation frames, with mipmaps.
- It draws the driver in the race (one-player ARCADE, your seat), in
  water and mud, with its mirror image on ice, and in the driver select.
  Eight different drivers of 30000 triangles each in one race at 4x
  resolution: 12.3 ms CPU and 1.3 ms GPU per frame at the 99th
  percentile, at most 587 MiB of memory.
- With the kart wheels hidden or with wheels of its own: a file that
  shows the kart wheels and has no wheel model keeps its classic model
  (the log says why). rldpack make-char --native-model on needs
  --wheel-model or --wheels off; Reload Studio builds the high-detail
  model only with "Show kart wheels" off or a wheel model and says so.
- OPTIONS -> GRAPHICS -> NATIVE DRIVERS: OFF or PREVIEW, OFF by
  default. PREVIEW switches the high-detail model on without a start
  switch. The choice is saved in ctr-settings.cfg (video nativedrivers)
  and applies at the next start; until then the page says "NATIVE
  DRIVERS: AFTER RESTART". It draws from RESOLUTION 2x; at 1x the
  classic model is drawn.
- For tests, switched on for one run and never saved: ctr_native.exe
  --dev --native-preview (--native-filter nearest|linear for the
  textures), and ReloadStudio.exe --enable-preview-features, which
  builds it for every OBJ with the kart wheels hidden.
- The classic model is always in the file as well. A game with NATIVE
  DRIVERS off and without --native-preview, and every older version,
  draws the classic model; a fault in the high-detail part never
  refuses the file.
- Wheels of their own (WHLS version 2 in the CNET chunk): one wheel
  model for all four wheels, an OBJ (with its MTL file and one texture,
  each side a power of two up to 1024) or a PLY, at most 1024 triangles
  and 2048 vertices, one material. The right wheels are drawn as its
  mirror image, the front wheels steer, all four roll with the speed;
  their tint follows the body, also in water and in the mirror.
- For scripts: rldpack make-char --wheel-model <obj|ply> and
  --wheel-size 50..200 (percent of the game's wheel; the bottom of the
  wheel stays on the ground). --native-model on needs --wheel-model or
  --wheels off. Too many triangles or a texture over 1024 is an error:
  a wheel is never reduced or scaled. rldpack info names the wheels
  (WHLS version 2, triangles, radius).
- With --wheel-model the classic model keeps the kart wheels: where the
  high-detail model is not drawn (NATIVE DRIVERS off, 1x, an older
  version) the character drives its classic model with the game's own
  wheels. Older versions refuse a version 2 wheel and draw the classic
  model.
- Wheels of their own, complete (WHLS version 3, written only when one
  of these switches is used or a tread count is stored, see below;
  otherwise version 2 as before):
  --rear-wheel-model <glb|obj|ply>: a wheel of its own for the two rear
  wheels, with the same limits and its own material and texture; it
  keeps its size next to the front wheel as in the two files.
  --axle-front and --axle-rear <fwd>,<up>,<track>: moves the wheels of
  that axle, in model units (fwd -32..32, up -16..32, track -32..64 for
  the whole track; each wheel moves by half).
  --wheels-always on|off is reserved: on sets a flag of version 3 that
  has no effect in the game (wheels of their own are drawn at every
  distance anyway); Reload Studio does not pass it.
  --wheel-model and char-wheel take a .glb as well.
- Wheels of their own no longer look still or as if they turn backwards
  at top speed. When the character is built, make-char counts the lugs
  of the tread from the shape of each wheel model (front and rear): 4 to
  32 lugs, all alike, with a groove between each two. Only a count that
  is certain goes into the file, and the game then turns the drawn wheel
  by at most 0.30 of the spacing of its lugs per frame. A wheel without
  a count (a smooth one, or one whose tread cannot be counted for
  certain) gets a limit that is safe for any tread of up to 32 lugs: at
  top speed it may seem to turn slower than the kart drives, but never
  backwards or standing still. Only the drawing changes. The count is
  stored only when every patterned part of the wheel repeats exactly that
  often: lugs, groove floors, and also spokes or bolts on the rim (smooth
  round parts do not matter). 8 spokes on 4 lugs, or 12 spokes on 10
  lugs, mean no count and the safe limit. Model spokes and lugs as
  geometry, in step with each other: a pattern only painted in the
  texture (stripes, painted spokes) is not counted and can still flicker.
- For scripts: make-char prints @value wheel-treads front|rear <n>
  found|not-determined, and without a count info wheel-treads with the
  reason; rldpack info names the count. A character with wheels of its
  own built before this version has no count: build it again once.
- Older versions skip MRPH (no win and lose; the high-detail model is
  drawn as before) and refuse WHLS version 3 (rule CNET-10): a file with
  a rear wheel model, moved axles or a stored tread count gets its
  classic model with the game's own wheels there.
- Reload Studio: "Native model" (tab Extras, card Import) and the card
  "In the race" are open without a start switch, marked "Preview
  feature". The new card Wheels takes a wheel model (glTF, OBJ or PLY)
  and its size and spins and steers the wheels in the preview. Without
  the tick Reload Studio builds the same file as before.
- Reload Studio preview of the high-detail model: drawn as the game
  draws it with NATIVE DRIVERS set to PREVIEW, with the real textures in
  full size (up to the game's limit) and the same mipmaps as the game.
  When the character has both models, the View menu switches between
  Native and Classic (the model the game draws with NATIVE DRIVERS off).
  The line below the preview says which look you see and why, and names
  the texture files that were not found; such a material is drawn in its
  colour.
- Wheels of their own in the preview: at the kart's wheel points,
  spinning and steering, also without a body model (then on the Crash
  size kart). The card Wheels reads the wheel again when it was exported
  again (or its texture was put in place), shows the reason for a
  warning (a texture not found, an axle that is not X), takes Browse and
  Clear at once, and finds the wheel texture in the Textures folder as
  well. When the preview shows wheels the character will not have, the
  card and the line below the preview say so.
- Reload Studio, card Wheels: "Rear wheel model (GLB/OBJ/PLY)" and
  Front axle or Rear axle with Fwd, Up and Track. The preview shows
  the rear wheel at its size and the moved axles at once. Each of these
  goes to make-char only when it is set.
- While the card Wheels is shown, a .glb, .gltf, OBJ or PLY dropped
  onto the Character page becomes the wheel model; the body keeps its
  file.
  Elsewhere a dropped model is the body, as before.


NEW IN 0.0.5 BETA
-----------------
- Custom characters: Reload Studio (page Character) builds a driver from a
  PLY or OBJ model - OBJ with its MTL and PNG/JPG/TGA/BMP textures - with a
  portrait, a mask (Aku Aku or Uka Uka), voice clips and the kart wheels
  drawn or hidden. The model is fitted to Crash's size, repaired and, above
  the limit, reduced; the preview shows it next to Crash and in the steering
  poses. The file goes into the "characters" folder next to the game; restart
  the game to see it in the driver selection.
- NITRO-PIT: the MODE panel on the laps box, and Time Trial with its own
  best times.
- Reload Studio follows the Windows display setting (100 %, 125 %, 150 %),
  shows what it reads from a model (format, materials, textures, groups),
  and can cancel a long check or build.
- Fixes: concave quads are split correctly; a model with seams between its
  parts is fitted to the right size; the preview matches the game's
  rounding; up to 128 colors per character; large models say beforehand how
  long their reduction takes.


NEW IN BETA 0
-------------
- The Alpha-Maker is now called Reload Studio (ReloadStudio.exe; Beta 0
  shipped it as alphamaker.exe). Its settings move once from alphamaker.ini
  to reloadstudio.ini (the old file stays); its test and preview logs are
  now in %TEMP%\Reload Studio.
- A track with a broken minimap table no longer crashes the race; it shows no
  minimap. Reload Studio warns about it.
- Object limit: Reload Studio refuses tracks with more than 110 placed
  objects and warns above 90. If the game ever runs out of room, it says so
  in the log and leaves out an effect (an explosion, a flame) instead of
  crashing.
- Folder and file names with any characters work (for example a Windows user
  name with accents or Cyrillic letters).
- Logs are kept: every start writes a new log with date and time in the
  "logs" folder, the last 5 stay. Reload Studio keeps its last 5 test and
  preview logs the same way.
- OPTIONS -> GRAPHICS: display mode, aspect ratio, resolution, anti-aliasing.
  Saved and restored at the next start.
- Track previews in the track selection screen. "Build container" in
  Reload Studio records the preview by itself, in the background (about 20
  seconds, no game window). The preview shows a drive along your track from
  the driver's view (needs bot data / nav paths; without them a camera flies
  along the restart points). If the preview cannot be recorded, the
  container is still built, and Reload Studio says why ("preview skipped"
  or "preview failed"). A preview game that has not finished after 2 minutes
  is stopped.
- Reload Studio checks that the game next to it is from the same package.
  If the game it remembered from an earlier session is from another package,
  it switches once to ctr_native.exe in its own folder and says so.
- Crystal Challenge for custom tracks: ARCADE -> NITRO-PIT -> CRYSTAL. Collect
  every crystal before the time runs out. Win or lose, you get RETRY or back
  to NITRO-PIT; nothing is written to your adventure save. Reload Studio
  ticks every mode your track has the data for.
- CTR Challenge for custom tracks: ARCADE -> NITRO-PIT -> CTR. Win with 1st
  place and all three letters C, T and R. Win or lose, you get RETRY or back
  to NITRO-PIT; nothing is written to your adventure save. The track needs
  each of the letters C, T and R exactly once; bots need nav paths.
- A track that offers several modes is listed under each of them (RACE,
  CRYSTAL, CTR). Cups are race only.
- Custom tracks start without the camera fly-in before the countdown, even
  if the track has its own camera path. Disc tracks keep their fly-in.
- "Build container" sets the ids of the letter models c, t and r by their
  names, so the HUD shows C T R in that order. When it changes one, it says
  so in its messages.
- Custom characters: put .rldchar files into the new "characters" folder next
  to the game. Each gets a tile in the one-player ARCADE driver select, after
  the original drivers (at most 32). A broken file is skipped, the game starts
  anyway and the log says why.
- Reload Studio has a new page "Character": a PLY model of driver, steering
  wheel and kart, a name, a driving style, a size, an optional icon and an
  optional voices folder. It checks while you type, shows the model as the
  game will draw it (turnable, three poses, on Crash's kart) and
  builds the .rldchar. The page always builds on Fake Crash; it asks for no
  original driver to start from.
- The driving style (Balanced, Acceleration, Speed, Turning) decides how a
  custom character's kart drives and its engine sound.
- The size makes only the driver and the steering wheel larger or smaller;
  the kart keeps its size. Visual size only - physics and collision follow
  the driving style.
- Crash is the standard size: every character model is fitted to the size
  of Crash with his kart, whatever scale it was exported in. Its kart gets
  the length of Crash's kart (112.4 game units); with "Show kart wheels" off
  the whole model gets that length. It never gets taller than the tallest
  original driver. The size slider works from there: 100 % = Crash size.
  The preview shows a dashed "Crash size" box. For scripts: rldpack
  make-char --fit crash is the default; --fit none keeps the exported size
  and is the only mode that takes --scale, so a script that passes --scale
  now needs --fit none as well.
- Automatic reduction: a model with more triangles than the game has draw
  memory for (805 triangles without textures - as much as N. Oxide, the most
  any original driver uses) is reduced to at most 797 triangles, only as far
  as needed. The shape and the colours stay, kart, driver and steering wheel
  are reduced each on its own, and the same model always gives the same
  result. Reload Studio shows the triangles and the draw memory before and
  after and says "reduced automatically". The check box "Reduce
  automatically" (on by default; rldpack make-char --reduce off) brings back
  the old refusal.
- Faces with more than four corners are split into triangles; only faces
  that cannot be split (twisted, or without area) are still refused.
- Kart wheels on or off: the check box "Show kart wheels" (on by default;
  rldpack make-char --wheels off) is stored in the .rldchar. Off is for
  models that bring their own wheels or their own vehicle: the game then
  draws no kart wheels (and no wheel reflections) for that driver; tyre dust
  and skid marks stay. An older game ignores the setting and draws the
  wheels. Details of the file: docs/CONTAINER_FORMAT.md in the source code.
- A custom character's icon now shows on its tile in the driver select, for
  the first 20 files the game loads (refused files do not count). Without
  an icon, with a broken one and from the 21st loaded file on, the tile
  shows the portrait of Fake Crash; the log
  line "[CTR Char] portrait ..." says which.
- Repair the model: the check box (on by default; rldpack make-char
  --repair off) welds split corners, drops triangles without area and
  doubled ones, turns faces outward, splits cracks and closes holes of up
  to 8 edges. Reload Studio says what it changed.
- Draw open parts from both sides: the check box (on by default; rldpack
  make-char --open-parts one-sided) draws the triangles of parts that are
  still open after the repair from both sides, so you cannot look into
  them from behind. It costs no triangles.
- Closed hull (remesh): the check box (off by default; rldpack make-char
  --remesh on, with --remesh-resolution 32..128) replaces kart, driver and
  steering wheel by closed hulls of their surface, then reduces them and
  takes the colours over from the model. Only for a model the repair
  cannot fix; it needs "Reduce automatically".
- Better reduction: colours always stay in their place and no face ever
  turns to the back. Colour borders and sharp edges are guarded as well;
  if the target cannot be reached that way, the reduction first drops
  these guards and then, if needed, its colour cost, and says so.
- The model is placed onto a reference kart: an original kart at Crash's
  size with his seat and steering wheel. Your kart sits at the height and
  in the middle of Crash's; the size slider and the lean when steering
  work about Crash's seat (with "Show kart wheels" off: about the bottom
  of the driver). Parts of a vehicle across the middle of the
  kart (a body, a fork, a seat) stay still with the kart. The preview
  shows this reference with the game's kart wheels (on or off) instead of
  an original kart beside the model.
- Every one of the 47 animation frames is read back as the game reads it
  before the file is written. A value that would be cut off in the packing
  is an error (model-quant). Thin triangles that the packing turns over in
  some frames are drawn from both sides, so they leave no holes.
- For scripts: rldpack make-char --diagnose <file> writes the model as
  every step saw it (text) and never a character.
- Reload Studio finds the game only in two places: the program chosen on
  the "Test in game" page (Browse), otherwise ctr_native.exe in its own
  folder. It no longer searches other folders; when the game is missing,
  the page says how to choose it.
- Reload Studio --settings <file.ini> (for automation and tests): settings,
  logs and temporary files only in that file and its folder, nothing in
  %APPDATA% or %TEMP%.


KNOWN ISSUES
------------
Modes and menus
- Custom tracks play Race (also as Time Trial), Crystal Challenge and CTR
  Challenge. Battle is planned.
- Time trial: the HUD keeps TIME at the top left, the rank column and the
  wumpa counter. A new record and a new best lap in one run show only NEW
  RECORD; the best lap is in the file. There is no ghost.
- Multiplayer (VS., BATTLE, 2 players) is locked.
- A track that offers both Race and Crystal Challenge is not tested yet: no
  test track has both restart points and crystals.
- Crystal Challenge has a fixed time limit of 3:00 for every track for now.
- CTR Challenge: letters that the exporter wrote without a collision hitbox
  cannot be collected, so the challenge cannot be won. Reload Studio does
  not check this yet.
- No bots and no auto drive on tracks without nav paths. In a CTR Challenge
  1st place is then easy.
- With exactly two tracks in the folder, the track wheel can show two names
  on top of each other after you scroll it.

Characters
- Custom drivers without their own voice lines are silent. With voices a
  driver says nothing at an event it has no clip for.
- The character's own icon shows only for the first 20 loaded files; high
  score lists and profiles show the portrait of Fake Crash.
- The cup podium shows the template (Fake Crash, for a character from
  Reload Studio) in place of the custom driver.
- Only in the one-player ARCADE driver select; not in NITRO-PIT CRYSTAL or
  CTR, the original Time Trial, Adventure, Battle or with two players.
- The size is visual only - physics and collision follow the driving style.
- With "Show kart wheels" off, tyre dust and skid marks still show where the
  game's wheels would be.
- High-detail model (preview): drawn only with NATIVE DRIVERS set to
  PREVIEW (or --native-preview) and only from an internal resolution of
  2x; at 1x the classic model is drawn.
- NATIVE DRIVERS applies at the next start, not right away.
- High-detail model: a file that shows the kart wheels and has no wheel
  model gets the classic model only.
- High-detail model: a semi-transparent (blend) material makes the game
  draw the classic model for that driver.
- High-detail model: only from an OBJ or a glTF. A PLY names no texture
  file, so it gets the classic model only (Reload Studio says so).
- The format of the high-detail model is a preview and may change.
- Exhaust points belong to the model as it was fitted. After a change of
  size or fit, set them again.
- The fitted shadow is computed from the model's footprint with start
  values; it may cover a little more or less than the model.
- Wheels of their own are always drawn, also where the game leaves its
  own wheels out (lower level of detail); --wheels-always has no effect.
  In the mirror and under water they are darkened like the body.
- A wheel size other than 100 % shows only on the high-detail model; the
  classic model drives with the game's wheels at their normal size.
- The wheel points do not follow the size of the driver (--size).
- Wheels of their own: when the lugs cannot be counted for certain from
  the shape of the wheel (a smooth wheel, lugs that are not all alike,
  spokes or bolts that do not repeat as often as the lugs, or a tread
  painted only in the texture), the game uses the limit that is safe for
  up to 32 lugs, and at top speed the wheel seems to turn slower than the
  kart drives. A painted pattern with more repeats than the stored count,
  or than 32, may still flicker at speed.
- Wheels of their own built before this version carry no tread count
  and get that safe limit; build the character again once.
- Win and lose show only on the high-detail model (--native-model on,
  in Reload Studio "Native model") and only after a race with a real
  placing; the classic model stays neutral after the finish line.
- At the finish line the high-detail driver first jumps a little from
  its steering pose, then blends into win or lose (the blend starts from
  the neutral pose).
- Rigs (a glTF with a skin) are not supported yet; animations come only
  from shape keys.
- glTF: a texture rotation (KHR_texture_transform) is not used (warning
  gltf-texture-rotation); the weights of the shape keys in the file are
  ignored (the base mesh is the neutral pose).
- rldpack: for a file with moved axles the text line "wheel ... at" of
  make-char still names the game's wheel points, and rldpack verify does
  not name the section MRPH; the @ lines are right.
- The shadow in Reload Studio's preview is a soft rectangle; the game's
  shadow can look a little different.

Previews
- The invisible kart still hits crates and fruit, so they break in the
  preview. If it falls off, the mask carries it back.
- Without nav paths the camera flies along the restart points; it does not
  avoid walls and ceilings and may pass through a tunnel roof.
- A track with only Crystal Challenge gets no preview.

Tracks and sound
- Very large tracks: flickering holes near the camera are possible when a
  track has very coarse BSP leaves. The log then contains "rendered list
  full" - please report it, with the track's file name and SHA-256.
- Tracks exported with Saphi: a hit may be missed where hitboxes are
  duplicated, and some floors may be black. Always build with "Build
  container"; it fixes wrong model ids.
- Music banks above 512 KB load, but their playback is not fully tested yet.
  The ambient sound set under "Advanced" is not tested either.

Programs
- Reload Studio starts the game in developer mode for "Start game" and for
  the preview recording. That is intended.
- The programs are not signed. Some virus scanners may warn about them or
  move them to quarantine; then allow them in your scanner.
- Retail cheat codes that unlock drivers are not saved to the memory card;
  all drivers are available from the start anyway.
